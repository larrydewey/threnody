# Threnody for Linux

A desktop messenger on [`threnody-ffi`](../../crates/threnody-ffi), the API the [Android app](../android) uses, written with GTK 4 and libadwaita. It follows the Android app's design and wording, laid out for a desktop: conversations on the left and the open chat on the right. Narrow windows show one pane at a time.

```sh
apps/linux/install.sh               # build, then install for this user (~/.local); quits and restarts a running copy
cargo run -p threnody-desktop       # or run it from the source tree
cargo run -p threnody-desktop --no-default-features --features nfc   # without calls: no prebuilt WebRTC (for builds from source only)
```

It needs GTK 4.14 or newer and libadwaita 1.5 or newer, plus their development headers to build. On Debian or Ubuntu that's `libgtk-4-dev libadwaita-1-dev`, on Fedora `gtk4-devel libadwaita-devel`, and on Arch `gtk4 libadwaita`. The keyring is used through the Secret Service, so `libdbus-1-dev` is needed too. Tapping a phone (the `nfc` feature, on by default) links `libpcsclite`: `libpcsclite-dev` to build on Debian or Ubuntu, `pcsc-lite-devel` on Fedora, `pcsclite` on Arch; build with `--no-default-features --features calls` to leave it out (`--no-default-features` alone also leaves out calls). Video calls read the camera through GStreamer: `libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev` (Debian, Ubuntu), `gstreamer1-devel gstreamer1-plugins-base-devel` (Fedora) or `gstreamer gst-plugins-base` (Arch), with the `v4l2src` element from the good plugins (`gstreamer1.0-plugins-good`, `gstreamer1-plugins-good`, `gst-plugins-good`).

**One identity with the CLI.** The app uses the CLI's data directory (`$THRENODY_HOME`, else `~/.local/share/threnody`) and the same keyring entry. An identity created with `threnody init` opens without a prompt, and one created here works with the CLI. Don't run both on the same directory at once: two nodes with one identity fight over sessions. Only one copy of the app runs per data directory. If port 7450 is taken, the app picks another and keeps it for later runs, so invites stay valid.

**Key protection, on by default.** A new identity is sealed (Argon2id) with a random key kept in the system keyring (GNOME Keyring, KWallet, KeePassXC). An identity stored unprotected, from an older CLI, is sealed this way when the app first opens it. Without a keyring the app asks for a passphrase, and stores the key unprotected only if you choose that explicitly. Identities sealed with a passphrase of your own ask for it at start.

What it does:

- **Conversations.** Contacts and groups with their last message, unread counts and a dot for connected contacts. Message requests and group invitations come first. Tabs show all conversations, chats or groups, and folders of your own (the chats in each or rules for which belong, notifications and quiet hours). Right-click a conversation to pin it to the top, archive it, put it in folders, clear it or delete the contact.
- **Search.** *Search all messages* above the list finds messages in every conversation, and a chat's own search steps through its matches. History is searched in memory; no index is written.
- **Chat.** Encrypted history with ticks: one when sent, two once a device of theirs acknowledges, and "✓ 1/2" in groups until every member has. Enter sends and Shift+Enter starts a new line. The smiley button beside the message box inserts any emoji. Text sent to an offline contact is sealed for mailboxes. Links ask before they open.
- **Photos and files.** Use the attach button or drag files into the chat. The send dialog shows each photo, with *Edit* on it. You can add a message and mark them *sensitive*, so the recipient sees a cover until they click it. A sensitive photo is covered in the chat whether you sent or received it, and clicking the cover opens it in the viewer, never in the chat. Photos sent together form an album, shown as one bubble with a grid of the photos; *Forward* and *Delete* on it take all of them. Photo metadata is removed before sending unless you turn that off. Formats the node can't strip (HEIC, AVIF, TIFF, BMP) are sent as JPEG, and one that can't be read isn't sent. GIFs play in the chat. Received photos stay in the data directory (`media/`), as do files marked *sensitive* and files in chats whose messages disappear. Other files go to *Downloads/Threnody*. What is kept in the data directory is removed within a quarter of an hour of its message being deleted or disappearing; ones kept in *Note to self* stay. The ⋮ menu → *Media, files and links* has a tab each for a chat's photos, files and links, from its last 10,000 messages; sensitive photos stay covered there too, and links ask before they open in the browser.
- **Photo viewer.** Clicking a photo opens it in Threnody, not in another app: double-click, Ctrl+scroll or pinch to zoom, drag to move around, and `+`, `-` and `0` to zoom in, out and back. GIFs play. The ⋮ menu has *Save a copy…* and *Open in another app*. Photos are decoded at a bounded size off the main thread (GIFs, which play, are decoded in full once their size is checked), and pictures over 100 megapixels are refused.
- **Photo editor.** *Edit* in the viewer or the send dialog draws on a photo (three pen sizes) or puts text on it (click to add, drag to move, scroll or pinch to resize, click to change or remove), in eight colours, with *Undo* (Ctrl+Z), as the Android app's editor does. The result is a fresh JPEG with no metadata. Edited from the viewer, it can be sent in that chat (still sensitive if the photo was) or saved; edited in the send dialog, it replaces the photo there. Edits wait in the identity's own `edited/` directory, readable only by you, until they are sent, saved or thrown away.
- **Voice and video messages.** The microphone and camera buttons beside the message box record a voice message (up to 10 minutes) or a video message (up to a minute, with a preview); *Send* sends it, *Cancel* deletes it. They play in the chat, the Android app's included, and are kept in the data directory with photos. Recording uses GStreamer's `opusenc`, `oggmux`, `vp8enc` and `webmmux` (base and good plugins). Playing the Android app's H.264 and AAC needs `gst-libav` (or `gstreamer1.0-libav` on Debian and Ubuntu), and GTK's GStreamer media backend (`libgtk-4-media-gstreamer` on Debian and Ubuntu).
- **GIFs.** The GIF button searches GIPHY, once you agree to GIPHY seeing your searches and this computer's IP address (Preferences → *GIF search with GIPHY*). The GIF you pick is downloaded here and sent like a photo, so your contact's device never contacts GIPHY. Without that, it offers GIF files of your own. A build without `GIPHY_API_KEY` set asks for a key once.
- **Reactions, editing, deleting.** Right-click (or long-press on a touchscreen) a message to react, reply quoting it, forward it, pin it, copy, edit your own, delete it for you, or delete it for everyone. A chat keeps its unsent draft, and *Note to self* is a chat with yourself on all your devices.
- **Send later.** Right-click (or long-press) the send button, or press Ctrl+Enter, to schedule the message: in an hour, this evening, tomorrow morning, or a date and time up to a year ahead. A bar above the message box shows what is scheduled in that chat; click it to send one now, edit its text, change its time or delete it. This computer sends it while Threnody runs (closing the window keeps it running unless Preferences make closing quit); quitting with messages scheduled asks first. A message that would go out more than a day late is held for you instead. Scheduled messages are stored encrypted, never synced or backed up, and look like any other message to the recipient.
- **Calls.** The call and video-call buttons in a contact's chat start a voice or video call (Appendix Q); a bar across the top of the window shows a call that rings or runs, with mute, camera, hang up and reactions. While the window is in the background, a call rings with a notification that answers or declines it; a video call's offers *Voice* and *Video*. A build without the `calls` feature (on by default) has no call buttons and tells contacts it doesn't take calls, so they don't ring it; a group call doesn't ring it either, and it can't start or join one.
- **Polls, mentions and notifications.** *New poll…* in a group asks a question with options. Typing `@` offers the group's members. A chat's ⋮ → *Notifications* chooses all messages, only mentions and replies (in groups), or none.
- **Lists.** The lists button opens checklists you can share with contacts and edit together.
- **Trust.** The chat shows a banner when a contact is new, unapproved, unverified, or has added a device you haven't verified. *Compare* shows the safety number, and *They match* marks it verified. The ⋮ menu also renames, approves or revokes, sets the disappearing timer and shares your profile.
- **Invites.** The QR button shows your invite as a QR code and a link. The link carries up to four of this computer's addresses (global IPv6 first) and, with internet reachability on, a key that finds it in the DHT after it moves ([Appendix S](../../docs/appendix-s-handles.md#invite-links)). *Preferences* → *Invite links* → *Reset invite links* replaces the key, so links shared so far stop finding this computer there. Clicking a `threnody://` link (or `threnody-link://` for linking devices, or `threnody-dir://` for a relay directory) opens the app with it filled in; nothing is dialled, joined or subscribed until you click. **+ → Scan a QR code** (also in *Add a contact*, on the empty list and in *Relay directories*) reads an invite, link code or directory link with the camera, from an image file, or from a copied image (Ctrl+V); frames stay on this computer and aren't kept, and the camera stops when the dialog closes. It uses GStreamer's `tee`, `videoconvert`, `videoscale` (base plugins) and `videoflip` (good plugins), as calls do. When the window becomes active, an invite, link code or directory link someone else's app copied is offered once (*Add the copied invite?*, *Join with the copied link code?*, *Subscribe to the copied directory?*); only up to 4 KiB of plain text is read, nothing is kept, and links of this account's devices and anonymous identities and directories already subscribed aren't offered. *Add a contact* and *Join another device's account* fill themselves in from a copied link.
- **Tap a phone.** With a PC/SC NFC reader attached (an ACR122U or similar, or a laptop's built-in one) and `pcscd` running, *Add a contact* has *Tap a phone*: hold a phone showing its invite (the Android app's *My invite*) on the reader, and its link fills in while it gets this computer's fingerprint, so you're each other's contacts once you connect ([Appendix T](../../docs/appendix-t-nfc.md)). Closing the dialog stops waiting. A computer can only tap, not be tapped, and an iPhone can't be tapped either.
- **Handles.** Preferences → *Your handle* makes a short handle such as `larry-7K3M-QX9P` that people can type into *Add a contact* to find you without an invite ([Appendix S](../../docs/appendix-s-handles.md)). Off unless you make one; *New code* replaces it and *Remove* drops it.
- **Groups.** Create a group (you own it), invite contacts, list and remove members, leave or delete it. Invitations from contacts who haven't approved you wait for *Join* or *Decline*.
- **Anonymous identities.** **+ → Anonymous invite** makes a separate identity with its own keys, conversations, files and port. It can burn itself after a day, a week or four weeks. Its chats are marked 🎭. *Reveal who you are…* in its chats proves to that contact that it is you. These are the CLI's personas, sealed the same way.
- **Volunteer relays and directories.** Preferences → *Relay directories* subscribes to a directory by its `threnody-dir://` link, typed, scanned or clicked (every identity, anonymous ones included, subscribes through links of its own). When your contacts can't relay for you, circuits then go through two volunteer relays, each paid with an anonymous token ([Appendix P](../../docs/appendix-p-volunteer-relays.md)). *Route through volunteer relays* is on unless switched off. *Volunteer as a relay* carries strangers' circuits through this computer at a public address you give (one that reaches its port, TCP and UDP), and *Run a relay directory* lists volunteers and gives out tokens, with its `threnody-dir://` link to share and a switch per registered relay. A directory reviews relays before listing them unless you switch that off; stopping it deletes it, so it doesn't start again. Both are off unless chosen, and never for anonymous identities.
- **Credentials.** A chat's menu → *Offer a credential…* vouches for attributes of that contact. *Ask for a credential…* asks them to prove some. Offers and requests from a contact wait in their chat with *Review*; *Later* (or Escape) leaves one waiting and tells them nothing. Nothing is shown unless you tick it, and proofs can't be linked to each other ([Appendix O](../../docs/appendix-o-credentials.md)). The main menu → *Credentials* lists those you hold.
- **Devices and profile.** Link a new device, join another device's account, rename devices, remove a lost or retired one, and edit your profile details. Messages sent from another of your devices show "from your other device" with their ticks. A file a contact sends reaches one of your devices, which tells the others, so it shows on all of them. Photos and voice and video messages from your other devices download by themselves on unmetered networks (up to 30 days old; never sensitive or disappearing ones); other files show a *Get* button. *Preferences* → *Get photos from my other devices automatically* turns the automatic part off. Files that come over are kept privately, never in Downloads. Nothing in your profile is shared until you choose, contact by contact.
- **Backups.** Preferences → *Back Up…* saves the identity, contacts and history to a file sealed under a passphrase you choose; *Restore from a Backup…* puts them on a new computer (Appendix C, *Backups*).
- **Always-on relay.** Preferences → *Always-on relay* picks a mutually approved contact, such as a [relay node](../../docs/relay-node.md) on a server, to keep a session with.
- **WireGuard tunnels.** Preferences → *Offer tunnels* (off unless chosen) offers tunnels to mutually approved contacts and keeps `wireguard/thr0.conf` in the data directory current; bring it up with `sudo wg-quick up` on that file (Appendix D).
- **Metadata protection, all on unless switched off** (Preferences): cover traffic (every 2 s, or every 10 s on a metered network), onion routing first, removing photo metadata, and reaching contacts over the internet. Notifications are private by default: they say "New message", without sender or text. With that off, a disappearing message's notification still leaves out its text, which would outlive it. Read receipts and typing indicators are sent unless switched off. Disappearing messages are off unless you choose a timer.
- **App lock.** Preferences → *App Lock* locks the window behind a PIN or passphrase. New identities (and existing installs, once) are offered it. It locks when the window is hidden or minimized (at once by default), after 5 minutes idle, when the screen saver starts, when the session locks (`loginctl lock-session`, hypridle, swayidle) and before sleep; the main menu's *Lock Now* locks at once. While locked, dialogs close, other windows hide, shortcuts do nothing and opened links wait, and every notification is one "New message" that names no chat. A call rings with a notification that says only "Incoming call"; it is answered after unlocking. The lock page shows after the identity passphrase too. Five wrong entries make it wait 30 s, doubling to at most an hour; *Erase after 10 wrong PINs* (off unless chosen) erases everything at the tenth instead. A *duress PIN*, entered instead of yours, erases everything and starts Threnody afresh. For an identity in the keyring, the lock file is keyed by a secret in its own keyring entry, so a copy of your files reveals nothing about it; otherwise a short PIN could be guessed from a copy, so choose a passphrase. App lock keeps people at your screen out of this window; it doesn't stop someone who can run programs as you (Appendix C, *App lock*). If the lock file can't be read (say the keyring was reset), the lock page offers only erasing; deleting `lock.cbor` from the data directory by hand turns app lock off.
- **Erase all Threnody data.** Preferences → *Danger Zone*, after you type `erase`, erases the identity and its keyring entries, contacts, history, anonymous identities, received files, *Downloads/Threnody* and the app's settings, then starts afresh (Appendix C, *Erasing*). Nothing is sent: contacts and your other devices aren't told. `threnody wipe` does the same from the CLI.
- **Nearby** (Preferences, off until switched on). *Bluetooth* advertises a private beacon only approved contacts recognise, and connects to them nearby without a network, as `threnody run --ble` does (BlueZ). *Join Wi-Fi Direct links* lets *Faster link (Wi-Fi Direct)* in a contact's chat menu ask their phone to host a Wi-Fi Direct group, which this computer joins through NetworkManager; its Wi-Fi leaves its usual network until the link ends, and returns a minute after no session runs over it. A computer can't host a group. Anonymous identities never use either.
- **Background.** Closing the window keeps the node running, so messages still arrive and notify. Launching Threnody again brings the window back, and *Quit* (Ctrl+Q) stops it. It also starts when you log in, with the window hidden, so contacts can reach you before you open it: each start writes `~/.config/autostart/org.threnody.Threnody.desktop` (running `threnody-desktop --background`), and Preferences → *Start when you log in* turns that off and removes the entry. The window shows anyway when your passphrase is needed, and when *Keep running when closed* is off. A build run from a source tree (`target/debug`, `target/release`) never adds the entry, and erasing all data removes it. While the window is hidden on a metered network or with power saver on, contacts are looked for less often. Preferences can make closing quit instead. It needs no push wake-ups: it stays connected, holds mailboxes for contacts' phones that sleep, and wakes them through the UnifiedPush endpoints they hand it ([Appendix R](../../docs/appendix-r-push.md)), with nothing to set up.
- **Diagnostics.** Fingerprints, the data directory, how the key is protected, the port, internet reachability, Bluetooth's state with *Scan Bluetooth* (and *Connect* for each device found) and *Leave Wi-Fi Direct*, and the node's event log. The log never records message text, credential attributes, group names or Wi-Fi Direct passphrases.
- **Looking contacts up.** Opening a contact's chat looks for them across the internet at once, in case they aren't connected.

Not yet here: a ringtone for incoming calls. The standby path on a second network (Appendix N, section 5) is Android's only, and UnifiedPush wake-ups aren't needed on a desktop that stays connected.

## Testing without a display

GTK's Broadway backend renders the app in a browser, which allows headless tests. The flows above were tested this way against the CLI, with throwaway homes: message requests, chat both ways, files and photos, reactions, safety numbers matching the CLI's, mutual approval, groups, and anonymous identities.

```sh
gtk4-broadwayd :5 &
GDK_BACKEND=broadway BROADWAY_DISPLAY=:5 THRENODY_HOME=/tmp/thr-a \
    cargo run -p threnody-desktop -- --gapplication-app-id=org.threnody.Test   # open http://127.0.0.1:8085
```

`--gapplication-app-id` lets a second copy run beside the one you use.
